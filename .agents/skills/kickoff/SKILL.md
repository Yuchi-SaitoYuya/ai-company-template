# 初回指示（kickoff）

CEO からの最初の指示を受け、**社員3名を動かして成果物を3つ出す**。

## 手順

### Step 0: 会社の前提を読む

`COMPANY.md` を読む。**社名が未記入（テンプレのまま）でも止まらない**。そのまま進めてよい。

読んだら CEO に1行で確認する:
> 「`<社名>`（`<何をする会社か>`）として3名を動かします。」

### Step 1: リサーチ社員とライター社員を並行して動かす

**リサーチ社員の完了を待たずに、ライター社員を起動する。**

- `researcher` に依頼: 「`COMPANY.md` を読み、競合リサーチを `output/research-<今日の日付>.md` に書き出してください」
- `writer` に依頼: 「`COMPANY.md` を読み、LP 文面を `output/lp-<今日の日付>.md` に書き出してください」

2人の作業は独立している（ライターは調べ物をせず `COMPANY.md` だけで書く）。
リサーチは約9分、ライターは約1分なので、直列にすると待ち時間が二重になる。
1回の応答でまとめて呼べればそれが最良だが、続けて2回呼ぶ形でも構わない
（サブエージェントは背景で走るため、どちらでも並行になる）。

**やってはいけないのは、リサーチの結果を受け取ってからライターを呼ぶこと。**

サブエージェントは**このチャットの会話を見られない**ので、依頼文には必ず「`COMPANY.md` を読むこと」と出力先パスを含める。

### Step 2: レビュー社員に両方を見せる

Step 1 の2ファイルが出そろってから `reviewer` を呼ぶ。

- `reviewer` に依頼: 「`COMPANY.md` と `output/lp-<日付>.md` を読み、レビュー結果を返してください」

`reviewer` は**書き込みツールを持っていない**ので、返ってきた指摘を**あなた（秘書）が** `output/review-<今日の日付>.md` に保存する。

### Step 3: CEO に報告する

3〜5行で報告する。成果物の全文は貼らない。

```
3名が動きました。
- リサーチ社員 → output/research-YYYY-MM-DD.md（競合N件）
- ライター社員 → output/lp-YYYY-MM-DD.md（キャッチコピー3案）
- レビュー社員 → output/review-YYYY-MM-DD.md（指摘N件・最重要は「…」）

次の一手: ①指摘を直す ②COMPANY.md を書き換えて作り直す ③社員を増やす
```

### Step 4: 次の一手を案内する

CEO が「指摘を直して」と言ったら、`writer` に**レビュー結果のパスを渡して**書き直させる。
これが「人間がルーターとして社員をつなぐ」ということの実演になる。

## 注意

- 途中でエラーが出ても止まらない。動いた社員の成果だけで報告し、失敗した社員は正直に伝える
- ネットワーク環境で Web 検索が使えない場合、`researcher` は「未検証」と明記して自分の知識で書く。それで正常
