# 競合リサーチ: Tsundoku Lab（ツンドク・ラボ）

> 調査日: 2026-07-26 ／ 調査方法: Web検索（掲載した URL は原則すべて実際に取得して内容を確認したものだけです。取得できなかったものは本文中に明記しました）

## 前提（COMPANY.md より）

- 「あとで読む」で溜まった記事を、読み切れる形に整理して届けるサービス
- 提供する価値は3つ: ①保存記事が自動でテーマ別に束ねられる ②「5分で読める分」だけを毎朝1通で届ける ③束ねたリストを URL 1本で人に渡せる
- COMPANY.md が挙げる競合: Pocket / Instapaper / ブラウザのブックマーク

以下は、その3つの価値を軸に競合を並べたものです。**各社の「弱み」は欠陥という意味ではなく、Tsundoku Lab の3つの価値と照らしたときの差分**として書いています。

---

## 要約（3行）

- **Pocket は 2025年7月8日にサービス停止済み**（データエクスポート期限とAPI停止は 2025年10月8日／出典: Engadget）。COMPANY.md が競合として挙げている Pocket は、現在は「競合」ではなく「移行先を探した層が残した空席」として見るのが正確だと思われます。
- 現存する主要プレイヤー（Instapaper / Readwise Reader / Raindrop.io / Matter / Cubox）は、**「保存・整理・検索・AI要約」を増やす方向**で競っています。一次情報で確認した範囲では、**「未読の記事を、毎朝、分量を固定して1通で届ける」機能を主軸に据えたサービスは今回見つけられませんでした**（=「無い」の証明ではなく「確認できなかった」です）。
- Readwise の Daily Review は「読み終えて**ハイライトした箇所**」の復習、Refind は「**Web全体から推薦した記事**」の配信で、いずれも Tsundoku Lab の②（自分が保存した未読分の毎朝配信）とは対象が異なると思われます（出典: readwise.io/read、refind.com）。

## この会社が狙える隙間（勝ち筋の仮説3点）

### 1. 「未読の山を、毎朝の1通に変える」ポジションが空いている可能性

一次情報で確認した範囲では、毎日のメール配信を主軸にしているのは Refind ですが、その対象は「Webから推薦された記事」と読める記述でした（出典: refind.com）。Readwise の Daily Review は「読了後のハイライト」を再提示するものです（出典: readwise.io/read）。
**「自分がすでに保存した、まだ読んでいない記事」を、分量を固定して毎朝届ける**——この一点を主軸に据えたサービスは、今回の調査では見つけられませんでした。
※これは「存在しない」という証明ではありません。個人開発アプリまでは網羅できていないため、**この仮説はローンチ前にもう一段確認したほうがよい**と思われます。

### 2. 「増やす」ではなく「減らす」を約束する設計

現存プレイヤーの公式サイトで確認できた機能の方向性は、AI Q&A（Cubox）、RSS/YouTube/EPUB対応（Readwise Reader）、重複検出・複数ビュー・全文検索（Raindrop.io）と、**扱えるものと機能を増やす方向**でした。
COMPANY.md の「増やすより減らす」「読まない記事は『読まない』と決めさせてあげる」は、この流れとはっきり違う立ち位置です。**機能比較の土俵に乗らないこと自体が差別化になり得る**と思われます。
（なお、24時間で自動削除する Burn 451 のようなサービスの存在は検索結果に出ましたが、公式一次情報を確認していないため**未検証**として扱います。）

### 3. 「束ね」と「共有」を1本につなげる

共有は Raindrop.io が最も進んでおり、コレクションを公開ページとして共有できます（閲覧側のサインアップ不要／出典: raindrop.io）。ただし**束ねる作業は手動**です。Matter の共有は引用画像（Quoteshots）が中心です（出典: getmatter.com）。
**「自動でテーマ別に束ねる」→「その束をそのまま URL 1本で渡せる」までが一続きになっている**構成は、今回確認した公式サイトの範囲では見当たりませんでした。①と③を分けずに設計することが、Tsundoku Lab の差分になり得ます。
