# AI社員の会社テンプレート

**あなたが CEO。AI社員が働く会社**を、自分のパソコンの中に作ります。

CEO（あなた）が指示を1つ出すと、社員が**前の人の仕事を受け継ぎながら**動いて、成果物が出てきます。

```
CEO（あなた）
   │  「うちの会社を動かして」
   ▼
秘書（Claude）
   │
   ├─① リサーチ社員 × 3人同時 ──────────────────┐
   │     ├ 同じことをやっている会社 ─▶ research-1-competitors.md
   │     ├ 別の方法で解決している手段 ─▶ research-2-alternatives.md
   │     └ 世の中の数字と使う人の本音 ─▶ research-3-market.md
   │                                              │
   │        3人の調査を渡す ◀────────────────────┘
   │           ▼
   ├─② ライター社員 ─▶ output/lp-YYYY-MM-DD.md      調査を踏まえて書く
   │        │
   │        └─ 調査 + 文面を渡す
   │           ▼
   └─③ レビュー社員 ─▶ output/review-YYYY-MM-DD.md  突き合わせて指摘する
```

**リサーチだけ3人がかりです。** 1人に全部やらせると9分かかる調べ物を、担当で割って同時に走らせます。
**同じ社員を何人も動かせる** — これがこのテンプレートで「増員」と呼んでいるものです。

---

## 必要なもの

これが揃っていれば、10〜15 分で動き出せます（成果物が出るまでは合計 25〜30 分ほどです）。

- [ ] **Claude Code のインストールとログイン**（**必須**）
  - 公式のクイックスタート（日本語）に従ってください → **https://code.claude.com/docs/ja/quickstart**
    - ステップ1 = インストール、ステップ2 = ログイン。ここまでで十分です
    - ターミナルを使ったことがない方は、同ページ冒頭の「ターミナルガイド」から
- [ ] **GitHub アカウント**（**任意**。無くても参加できます → [B の手順](#b-zip-から始める-github-アカウント不要)へ）

> 動作確認: ターミナルで `claude --version` と打って、バージョン番号が出れば準備完了です。

---

## セットアップ（10〜15分）

**A と B のどちらか一方**を選んでください。**A を推奨**しますが、GitHub アカウントが無ければ B でまったく問題ありません。

| | **A: GitHub から** | **B: zip から** |
|---|---|---|
| GitHub アカウント | 必要 | **不要** |
| 自分の GitHub に会社が残る | ○ | ✕ |
| 更新版を取り直せる | ○ | ✕ |
| あとから育てやすい | ○ | △（手元だけ） |

どちらも**やることは同じ**で、`3. その会社に入る` から先は共通です。

---

### A: GitHub から始める

#### A-1. 自分の会社リポジトリを作る（2分）

このページ右上の緑のボタン **「Use this template」** → **「Create a new repository」** を押します。

- **Repository name**: 好きな会社名（例: `my-ai-company`）
- **「Private」を選ぶ**（自分の会社に書いた内容が他の人に見えません）
- **「Create repository」** を押す

#### A-2. 自分のパソコンに持ってくる（3分）

作ったリポジトリのページで緑の **「Code」** ボタン → **「Download ZIP」** を押します。
ダウンロードした zip を**ダブルクリック**して展開してください。

`my-ai-company-main` のように**末尾に `-main` が付いた**フォルダができます。
ターミナル（Mac の「ターミナル」アプリ）を開いて、次を打って整えます。

```bash
mv ~/Downloads/my-ai-company-main ~/my-ai-company
```

`my-ai-company` の部分は、自分が付けたリポジトリ名に置き換えてください。

> **git を使い慣れている方**は `git clone` でも構いません。
> ただし Private リポジトリは認証（`gh auth login` や SSH 鍵）が必要です。
> 認証を求められて分からなければ、上の **Download ZIP が確実**です。

→ **[3. その会社に入る](#3-その会社に入る1分)** へ進んでください。

---

### B: zip から始める（GitHub アカウント不要）

#### B-1. zip を受け取って展開する（2分）

1. **`ai-company-template.zip`** を受け取ってダウンロードする
2. **ダブルクリック**して展開する（`ai-company-template` というフォルダができます）

#### B-2. わかりやすい場所に置いて名前を変える（3分）

ダウンロードフォルダに置いたままだと迷子になるので、**ホームフォルダへ移動**します。
ターミナル（Mac の「ターミナル」アプリ）を開いて、そのまま次を打ってください。

```bash
mv ~/Downloads/ai-company-template ~/my-ai-company
```

`my-ai-company` の部分は好きな会社名に変えてOKです。

> **うまくいかないときは**、Finder で展開したフォルダをホームフォルダ（家のアイコン）へドラッグしてください。それでも同じことができます。

→ **[3. その会社に入る](#3-その会社に入る1分)** へ進んでください。

---

### 3. その会社に入る（1分）

```bash
cd ~/<フォルダ名>
claude
```

`<フォルダ名>` は、A なら リポジトリ名、B なら `my-ai-company` です。
Claude Code が起動します。**ここからは日本語で話しかけるだけです。**

> **確認**: 起動したら `/kickoff` と打ってみて、候補に出てくればセットアップ成功です。
> **この時点ではまだ Enter を押さないでください**（次の手順で会社を自分のものにしてから流します）。
> 候補が出てこない場合は、フォルダの中で `claude` を起動できていません（`cd` を忘れていないか確認）。

## 自分の会社を動かす（12〜16分）

### 4. 自分の会社にする（5〜7分）— 触るのは `COMPANY.md` だけ

[`COMPANY.md`](COMPANY.md) の社名・事業・顧客・トーンを、自分の会社に書き換えます。
**このファイル1つを変えるだけで、社員全員の発言も成果物もまるごと変わります。**

> **架空の会社で構いません。** 実在する必要はまったくありません。
> 迷ったら「**文章のトーン**」を大きく変えてみてください。変化が一番わかりやすく出ます。
> 空欄が残っても大丈夫です。社員は「`COMPANY.md` に記載なし」と正直に書きます。

#### 書き換え方（エディタは不要です）

**専用のエディタを入れる必要はありません。** やり方は2つあります。

**① Claude に頼む（おすすめ・追加インストールなし）**

Claude Code の中で、日本語で頼むだけです。

```
COMPANY.md を見せて
社名を「ラーメン一途」に変えて、文章のトーンを職人っぽくして
```

CEO は指示を出すだけ。**これがこのテンプレートの本来の使い方です。**

> **承認を求められます。** Claude はファイルを書き換える前に、必ず変更内容を見せて
> 「この編集をしていいか」を聞いてきます。内容を確認して **`Yes`（許可する）** を選んでください。
> これは Claude Code が勝手にファイルを変えないための仕組みです。
>
> 保存ボタンを押す必要はありません。承認すればその時点でファイルは書き換わっており、
> **そのまま `/kickoff` を流せます**（`claude` を再起動する必要もありません）。

**② 自分で開く**

Finder でファイルを**ダブルクリック**すれば、お使いの Mac のテキストエディタ
（多くの場合「テキストエディット」）で開いて書き換えられます。
使い慣れたエディタがある方は、もちろんそれで構いません。

---

### 5. 動かしてみる（7〜9分）

`COMPANY.md` を書き換えたら、Claude Code の中でこう打ちます。

```
/kickoff
```

社員が順番に働き、`output/` フォルダに**5つ**のファイルが出てきます。
これで**あなたの会社が動きました**。

| | 出てくるもの | 目安 | 何をしているか |
|---|---|---|---|
| 1 | 調査メモ **3本** | **3〜4分** | リサーチ社員**3人が同時に**、別々の担当を調べる |
| 2 | LP文面 | +1〜2分 | **上の3本を読み比べてから**書く |
| 3 | レビュー | +2〜3分 | 全部と `COMPANY.md` を突き合わせて指摘する |

> ⏱ **最初の3〜4分は何も出てきません。** リサーチ社員3人が調べ終わるまで待ちます。
> **途中で止まって見えても正常です。** ウィンドウを閉じたり `Ctrl+C` を押したりせず、
> **そのまま置いておいてください**。
>
> ライター社員がリサーチを待つのは、**調査で見つかったことを文面に活かすため**です。
> 待たせないと、調べた内容がまったく使われない LP になります。

出てきたら、読んでみてください。

```
output のLP文面を読んで
```

> **`COMPANY.md` を書き換えて何度でも流せます。** トーンを大きく変えて流し直すと、
> 同じ社員が別人のように書くのがわかります（1回に7〜9分かかる点だけご注意ください）。

## 会社の中身

```
あなたの会社/
├── COMPANY.md          ← あなたが書き換えるのはここだけ
├── AGENTS.md           ← 就業規則（秘書と社員の共通ルール）
├── staff/              ← 職種1つ = 1フォルダ（人数はここでは決まらない）
│   ├── researcher/
│   │   ├── AGENT.md    ← この職種の役割・性格（職務記述書）
│   │   └── MEMORY.md   ← この職種の記憶（← あなたが育てる）
│   ├── writer/
│   └── reviewer/
└── output/             ← 成果物が出てくる場所
```

### 職種は3つ。人数は別の話です

`staff/` のフォルダは**人ではなく職種**です。1つのフォルダが1つ分の職務記述書で、
**そこに何人配属してもかまいません**。

| 職種 | 仕事 | できないこと | `/kickoff` での人数 |
|---|---|---|---|
| **リサーチ社員** | 競合・代替手段・使う人の本音を調べる | 会社の他のファイルを書き換えない | **3人**（担当を分けて同時に） |
| **ライター社員** | リサーチを読んで LP・紹介文を書く | 自分では調べない | 1人 |
| **レビュー社員** | 読んで指摘する | **書き込む手段を持っていない** | 1人 |

つまり `/kickoff` は **5人**を動かしています（3 + 1 + 1）。
リサーチだけ3人なのは、1人だと9分かかる調べ物を担当で割ると3〜4分で終わるからです。

**増員はフォルダを増やすことではありません。** 同じ職務記述書に人を足すだけです。
新しい**職種**が必要になったときだけフォルダを作ります。

レビュー社員が書き換えられないのは、お願いではなく**権限で担保**しています。
`staff/reviewer/AGENT.md` の `tools:` の行に、書き込み系のツールが入っていないためです。

**「誰に何を任せるか」「何を任せないか」「何人でやらせるか」を設計する** — これが一番の勘どころです。

---

## 大事な話: 「記憶」は AI が勝手に覚えるものではない

`staff/<社員名>/MEMORY.md` は、その社員の記憶です。

でも、**AI は記憶を持っていません。** 毎回まっさらな状態で起動し、その時に渡された文章しか見ていません。
「記憶しているように見える」のは、`MEMORY.md` を毎回読ませているからです。

→ **育てるのは CEO（あなた）の仕事です。**
社員がいい判断をしたら `MEMORY.md` に1行足す。ズレた仕事をしたら「次はこうして」を1行足す。
それが次回から効きます。これが「AI社員が育つ」ということの実体です。

## 次にやること

### 人を増やす（フォルダは作らない）

**同じ職種の人数を増やすだけなら、頼めば済みます。**

```
リサーチ社員を5人にして、担当を分けて調べさせて
```

これが一番手軽な増員です。1人でやると時間がかかる調べ物を、担当で割って同時に走らせます。

### 職種を増やす（フォルダを作る）

**今ない仕事を任せたいとき**だけ、新しいフォルダを作ります。
`staff/` に新しいフォルダを作り、`AGENT.md` と `MEMORY.md` を置いてから、こう頼みます。

```
staff/sales/ に営業社員を作りました。会社で働けるようにしてください。
```

リンクの設定まで Claude がやってくれます。

### 社員をつなぐ

レビュー社員の指摘を、ライター社員に渡して直させてみてください。

```
output/review-*.md の指摘を writer に渡して、LP を書き直させて
```

**指示を出す人間（あなた）が、社員と社員をつなぐ回線になっています。**
これを自動化していくのが、この先の話です。

## 困ったとき

| 症状 | 対処 |
|---|---|
| **`command not found: claude`** と出る | インストール直後はターミナルが古い状態のままです。**ターミナルを完全に終了（⌘Q）して開き直す**のが一番効きます。それでも出る場合は `~/.local/bin/claude` と打ってみてください |
| 途中で「使用量の上限」と言われた | 社員3名が順番に働くため、1回で多めのやりとりが発生します。しばらく待つか、上限の高いプランをご確認ください |
| `/kickoff` が候補に出ない | フォルダの**中で** `claude` を起動しているか確認（`cd ~/<フォルダ名>` を忘れていないか） |
| 社員が呼ばれず、秘書が自分で書いてしまう | `researcher と writer と reviewer を使って` と明示的に頼む |
| 「そのようなエージェントはありません」と言われる | フォルダを**コピーではなく移動**してください。一部のコピー方法で内部のリンクが壊れることがあります。zip を展開し直すのが確実です |
| リサーチ社員が「未検証」ばかり返す | ネットワーク環境で Web 検索が使えないときの動作です。**正常です**（確認できないものは「未検証」と明記する設計） |
| 成果物が出てこない | `output/` フォルダを確認。それでも無ければ「どこで失敗したか教えて」と聞く |

### zip を展開した方（A / B 共通）

| 症状 | 対処 |
|---|---|
| フォルダ名の末尾に `-main` が付いている | GitHub の Download ZIP はこうなります。`mv` で好きな名前に変えてください（手順 A-2） |
| フォルダが二重になっている | `名前/名前/` のように入れ子になることがあります。**`COMPANY.md` が直接見えるフォルダ**が正しい場所です |
| `mv` のコマンドでエラーが出る | 展開先が `~/Downloads` ではないのかもしれません。Finder でフォルダをホームフォルダへドラッグしてください |
| `cd` でフォルダに入れない | ターミナルに `cd ` と打ってから、Finder のフォルダを**ターミナルにドラッグ＆ドロップ**すると、正しいパスが入ります |
| `git clone` で認証を求められた | Private リポジトリでは認証が必要です。**Download ZIP に切り替える**のが確実です |
